# 000 哲学（中文翻译）

> 本文件是 [docs/000-philosophy.md](../../docs/000-philosophy.md) 的完整中文翻译；如有出入以英文原文为准。

dsh-superagent 是一个框架，也是一种与 agent 共事的方式。它的核心原则：

**占用尽可能少的人类注意力，给出尽可能多的价值。**

项目的每个部分都以其耗费的注意力来评判。一条消息、一个通知、一个问题、一项设置、一个面板元素、一段文档，都在耗费某个人的注意力；每一样都必须给出多于这份注意力的价值，否则就删掉。

## 对 agent 意味着什么

- **它只在被要求时、或在一条成文规则允许时行动。** 一个请求只有在直接面向 agent、且来自团队允许的人时才算数：在允许名单上，或在团队向请求开放的会话里。没人要求的工作需要团队写下的一条规则，而且以"只记录 agent 本会做什么"的模式开始。
- **它只在必须有人行动、或有人能用到结果时发言。** 它对请求确认一次，并说明自己要做什么。干活期间保持安静。结果就绪、需要决策、或无法完成时，它再次发言。消息简短，发到提出请求的那个会话。
- **它一次只问一个具体的问题，** 用结构化的形式，让问题抵达那个人，而不是淹没在长篇报告里。
- **它按影响收尾，而不是按投入。** 一个本地改动要做到可复审为止。一个需要设计决策的改动，停在一个清楚的问题上。
- **它如实报告。** 未完成的草稿标注为未完成；失败报告为失败；绝不为了免于开口而绕过限制。

## 对设计意味着什么

- **少的概念。** 设计只有它的领域概念（例如 Source）及其具体实现（例如 GitHub 和飞书）。一个业务需求成为其中某个概念的属性，或成为 agent 遵循的一段提示词；设计不会为它新增一个概念。
- **少的设置。** 当一个取值几乎适合所有团队时，默认值取代设置。团队用语言描述的行为是提示词文本，不是设置。
- **一个只展示"需要人"的面板。** 它把等人处理的东西排在最前。健康的状态不占空间。
- **按顺序阅读的文档。** 每篇编号文档只建立在它之前的那些之上，读者永远不会遇到一个尚未介绍的概念。

## 责任

agent 用你的团队每天都能看到的账号评论、开 pull request、给人发消息。它发出的每条消息都在耗费同事的注意力，而你要为之负责。agent 能做的事越多，它的运营者欠团队的就越多：

- **从窄开始。** 以一份短的允许名单、且主动工作只记录不执行来起步。等"它本会做什么"看起来是对的，再把两者放宽。
- **为更少噪音调优。** agent 吵了，就把提示词改短改严，或者暂停它。不要用更多的消息去解释噪音。
- **不要用它冲产量。** 批量 pull request、广播消息、为忙而忙，耗掉的比给出的多。
- **为它说的话负责。** 读它以你的名义发的东西；它说错了，就在提示词里纠正。

目标是在正确的时间给出正确的帮助，此外的任何时间什么都不做。
